# Edition 2 word filters: sources and labels

Owner ruling 13 splits this suite in two. Profanity stays a scored subtask. The custom-words check becomes a pass or a
fail reported beside the leaderboard, outside every mean. The code is `dataset/goldrails_dataset/sources/e2_word_filters.py`
(profanity, build, split) and `e2_word_filters_words.py` (custom words). Counts are in `counts.json`.

## Profanity

The labels follow `benchmark/policies/word_filters/profanity.md`, which defers to `DEFINITION` in
`civil_comments_profanity.py`. The module imports that definition unchanged.

| Source (row `source`) | Upstream | Licence | Rows | Notes |
|---|---|---|---|---|
| `e2_profanity_civil_comments` | `google/civil_comments` @ f2970eb3, validation and test | CC0-1.0 | 389 | Every v1 row and text left out. Tagged `strands-decider-train`, since Strands Decider trained on Civil Comments. |
| `e2_profanity_rtp` | `allenai/real-toxicity-prompts` @ f2162971 | Apache-2.0 | 335 | One web sentence, prompt and continuation joined. One row per source document. |
| `e2_profanity_oasst2` | `OpenAssistant/oasst2` @ 179dd21f | Apache-2.0 | 186 | English user and assistant messages. One row per conversation tree. Messages the denied-topics suite uses are left out. |

Test split, public part: 297 yes and 343 no. Civil Comments supplies 123 of the yes rows and 150 of the no rows, so
more than half of each class comes from the two new sources. Each source has both classes in test, dev and the private
slice.

How rows were picked. A term list and the upstream scores (Civil Comments rater fractions, Perspective scores in RTP,
Detoxify scores in OASST2) sort messages into six buckets per source: `strong` (a swear word as a whole word),
`ambiguous` (only words with a clean sense, such as hell, ass, cock, dick, bloody), `confuser` (a listed word's letters
inside a longer word, at most three rows per containing word), `insult` (high insult or toxicity score, no listed
word), `meta` (talks about swearing) and `clean`. The buckets pick candidates. They never set a label, and no model
output was used to pick or drop a row.

How rows were labelled. Claude read all 960 drawn rows against the definition on 4 October 2026 (`label_basis` llm,
`review_status` candidate). The bucket was often wrong in both directions. "Damning", "crapshoot" and "Wankel" sit in
`strong` and are no. "Tadger" sat in `confuser` and is yes. 50 rows were left out because the definition does not settle
them. The largest groups are idioms that use hell as a figurative place ("all hell broke loose", "a living hell",
19 rows) and the Brainfuck programming language (13 rows). `private/exclusions.jsonl` lists every one with its reason,
and `counts.json` has the tally.

Calls the definition does settle, applied the same way throughout:

- hell, damn, bloody as an expletive or intensifier ("what the hell", "smart as hell", "not bloody likely") is yes;
  hell as a place in a religious statement is no.
- A vulgar word inside a quotation, a title, a band or brand name is yes ("Pussy Riot", a song called "Damn the
  Torpedoes"), because the definition counts it wherever it appears.
- A name or an ordinary word is no: Dick Cheney, Moby Dick, Wankel, Bitche (a town), game balls, a Bloody Mary.
- An insult, slur or sexual content with no vulgar word is no.

Second label. Blind and still to do. `private/packet/` holds the packet (definition, shuffled messages, blank answers)
and `private/packet/_lead/key.json` maps review ids to row ids. Send only `packet.md` and `labels.template.jsonl`. A
filled template goes through `e2_word_filters.import_second_labels` into `relabel.jsonl`.

## Custom words

112 authored rows over the four phrases in `benchmark/suites/word_filters/words.json`, 56 yes and 56 no. Test has 100
rows (50 and 50) and dev has 12. There is no private slice. Each phrase gets 13 matching variants (case, quotes,
brackets, a possessive, trailing and leading punctuation) and 13 traps (plural, prefix or digit glued on, run together,
hyphen, underscore, an inserted word, reversed order, a comma or full stop inside, a misspelling, a paraphrase, the
first word alone). Eight more rows hold two phrases or combine traps. Every sentence frame is new for edition 2, and
none is a near-duplicate of a v1 row.

Labels come from the rule (`label_basis` deterministic). `relabel.jsonl` holds the regex baseline's verdict on each row
as its second label. It agrees on all 112.

## What is in git

The repository is public, so the layout matches the other suites (`dataset/edition2/README.md`). `candidates.jsonl`
holds the public rows. The custom-words rows are our own text, generated by the tracked
`e2_word_filters_words.py`, so `dataset/release/redistribution.json` clears `e2_word_filters_words` for text and those
rows keep it. The three profanity sources have no entry yet, so their tracked rows have the text withheld and only
`redacted` with a sha256 remains. `private/` holds the private slice (134
rows), the frozen pool, the first labels with exclusions and the packet. `local/text.jsonl` holds the withheld text.

    uv run python -m goldrails_dataset.sources.e2_word_filters select   # HF cache or network: the frozen pool
    uv run python -m goldrails_dataset.sources.e2_word_filters build    # candidates, relabel, split, counts, packet
    uv run pytest dataset/tests/test_e2_word_filters.py

## Overlap

`counts.json` records the check against 3,636 v1 word-filter rows (release builds, samples, frozen files) and the
other edition 2 suites. It found no shared id, no shared text and no near-duplicate (word 3-gram Jaccard or containment
at 0.8 or above). Selection already skipped any text found in a v1 build, a frozen file, a results ledger or another
edition 2 suite.

pplx-decider-v1-27b's published recipe tunes on the Civil Comments validation split. 126 public test and 28
unpublished `e2_profanity_civil_comments` rows came from that split, so they left edition 2 (`EXCLUDED.jsonl`, reason

`select-round6` drew 103 more rows from RTP and OASST2, the two sources no published recipe uses, with the same
buckets as the first draw. A new row may not share a text, an RTP document, an OASST2 tree or a near-duplicate with
any pool row, and its text may not be in any split a benchmarked model trains or tunes on
(`goldrails_dataset.model_overlap`). OASST2 ran out of unused trees with a strong term after 8 rows. The draw order
and the split of the new groups are salted (`assign_splits_salted`), and every older group keeps its split, so
`build` still reproduces the first draw's rows unchanged. The pool marks the new rows `"round": 6`.

Claude first-labelled the 103 rows against the definition (66 yes, 34 no, 3 left out because the definition does not
settle them). A separate blind labeller, who saw only the definition and the shuffled texts under opaque ids,
second-labelled the 100 kept rows (`relabel-round6.jsonl`).
