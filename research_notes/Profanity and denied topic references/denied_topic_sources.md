# Denied-topic (advice-topic) detection reference data: source verification

Scope: published datasets whose original labels mark whether a user message falls inside a specific advice topic (personal financial/investment advice, medical diagnosis/dosage advice, personal legal advice), for use as denied-topic reference data in a guardrail benchmark. Checked 2026-09-28. Revisions below are the Hugging Face commit SHAs / GitHub commits returned by the HF API and GitHub API on that date. Anything marked "(my inspection)" comes from downloading the pinned files and counting rows myself. Anything marked "Inference" is mine, not the source's.

## Q1. Per-candidate verification: what each source is, how it was labelled, and whether its label means "inside the topic"

### Takeaway
None of the verified sources labels user messages as inside/outside a finance, medical or legal advice topic with human labels and near-topic benign negatives. The sources split three ways: (a) hazard/refusal sets, where every row is a positive and the label means "should be refused / is hazardous" (AILuminate spc_*, Do-Not-Answer); (b) response-side "contains advice" sets with good near-topic negatives but no user-message label (BARRED `healthe`, HealthE); (c) system-prompt-relative on/off-topic sets that are LLM-generated and not advice-topic specific (GovTech off-topic, OffTopicEval, NeMo topical eval).

- Hosting and revision: HF `Plurai/BARRED`, commit `95c3015a917f5805148ae22270148b75ef6d6420`, lastModified 2026-04-05, card licence `mit`, not gated. - Card task definition (health): "Based on the HealthE benchmark (Gatto et al., 2023). Given a sentence or paragraph from a healthcare context, we generated a corresponding question to form a Q&A pair. The classifier predicts whether the agent's response to the presented question constitutes health advice. 200 samples were curated from the original dataset and processed to create the test set." Columns: `predicate`, `transcript`, `predicate_label`. Card table lists input type "Q&A", domain "Regulatory compliance (healthcare)". — [card](https://huggingface.co/datasets/Plurai/BARRED/raw/main/README.md)

- Negatives are near-topic health information (my inspection), e.g. a user question about what Kawasaki disease is, answered with a symptom description, labelled 0; a question about diathermy answered descriptively, labelled 0. Positives include "eat more vegetables and fruits" (label 1). — same parquet
- Paper on annotation: "For every task, we retrieved the existing annotations provided with the dataset and augmented them with additional annotations to ensure label balance and diversity." Table 1 caption: "Test sets include synthetic samples (Synth, human-verified) and human-curated samples (Human)"; for Health Compliance, Synth 123, Human 200. Paper's health task statement: "Given a sentence or paragraph, the classifier predicts whether it contains health advice. The original benchmark contains 3,400 advice samples and 2,256 non-advice samples. We sampled 20 instances for training seeds and 200 for testing." — [arXiv HTML](https://arxiv.org/html/2604.25203)

- Language: `en` (card metadata). — [card](https://huggingface.co/datasets/Plurai/BARRED/raw/main/README.md)

### Inferences
- Task equivalence, per source:
  - BARRED `healthe`: label means "this response contains health advice", i.e. topic presence, not harm. That matches denied-topic semantics, but on the output side. The user turn is a generated question, so it cannot serve as a user-message label without re-annotation.
  - HealthE: topic-presence labels (advice vs non-advice) on web health sentences, not user messages.
  - AILuminate spc_*: the hazard code is the prompt's elicitation category inside a safety benchmark. Violation is judged on the response (missing disclaimer). This is general policy compliance. The fin/hlt/lgl split does give per-topic, human-written user prompts, but only positives, and many are crime requests rather than advice requests.
  - Do-Not-Answer: "should not be answered" semantics (refusal). Advice harms are sub-labels on a positives-only, GPT-4-generated question set.
  - Aegis 2.0: unsafe-by-policy semantics with a noisy, merged "Unauthorized Advice" category. Its human prompt labels and safe rows are real, but safe rows are not near-topic advice negatives.
  - GovTech off-topic, OffTopicEval: relative to a system prompt. "Off-topic" means outside the deployment's scope, which is the inverse of a denied topic. In GovTech's data an investment-advice question can be on-topic for a finance bot.
- A denied-topic reference set built from these would need new annotation on at least the negative side. The most defensible positives are the AILuminate spc_fin/spc_hlt/spc_lgl prompts after re-labelling for "is an advice request". The best near-topic negative style is HealthE/BARRED (information vs advice), which would have to be recast as user messages.

### Gaps
- BARRED: the card and paper do not say who or what "generated a corresponding question" for each HealthE sentence. It is also unclear whether the 200 HF rows are exactly the paper's "Human 200" set or include the 123 human-verified synthetic rows. The HF release has 200 rows, which suggests the Human set, but that is an inference.
- HealthE: I could not verify from the Zenodo page how the 2,256 non-advice statements were selected or labelled (only entity-level annotation by 14 annotators is described). The Gatto et al. 2023 paper was not fetched.
- AILuminate: the Assessment Standard (Google Drive PDF) was not fetched, so the verbatim spc definitions come from a WebFetch summary of arXiv:2503.05731, not the standard itself. Per-prompt LLM-generation metadata is not in the demo CSV. Whether the demo CSV counts are exactly proportional to the practice set is not stated.
- Do-Not-Answer: venue (commonly cited as EACL 2024 Findings) is not confirmed on the pages I fetched.
- FinGuard-Bench: release URL, licence, query sources and label definitions are unverified; the counts come from a search snippet only.
- LegalAdviceReddit-style classification datasets and MedQuAD-style advice-vs-information sets: I found no published dataset with human labels for "legal advice request vs legal information question" on user messages. The one found (Kuk and Harasta) uses GPT-4o labels and has no stated release.

## Q2. Which source has human-made labels distinguishing an in-topic advice request from nearby benign questions?

### Takeaway
None at the user-message level. The closest human-grounded "advice vs near-topic information" labels are HealthE and the BARRED `healthe` test set, but both label advice in the response or passage, not in the user's request, and both cover health only.

### Cited Findings
- BARRED `healthe`: 99 advice / 101 non-advice, predicate "The agent's response contains health advice."; negatives are descriptive health information (my inspection). The paper calls the 200 test rows human-curated and derived from existing HealthE annotations. — [parquet](https://huggingface.co/datasets/Plurai/BARRED/resolve/95c3015a917f5805148ae22270148b75ef6d6420/healthe/test-00000-of-00001.parquet); [arXiv HTML](https://arxiv.org/html/2604.25203)
- HealthE: 3,400 advice statements from health websites and Preclude, and 2,256 non-advice statements. — [Zenodo](https://zenodo.org/records/7539391)
- Aegis 2.0: prompt labels are "always `human` annotated" and include safe prompts, but "Unauthorized Advice" is a harm category that also contains non-advice-domain role-play prompts (my inspection). — [card](https://huggingface.co/datasets/nvidia/Aegis-AI-Content-Safety-Dataset-2.0/raw/d86bb8bedff51d25ac834ab7838f1cc61acb7a2c/README.md)
- FinGuard-Bench claims expert query-level labels with a share of safe queries (about 27.1% implied by 72.9% unsafe), but release is unverified. — [arXiv abs](https://arxiv.org/abs/2605.29427); [PDF](https://arxiv.org/pdf/2605.29427)

### Inferences
- For finance and legal there is no verified human-labelled, near-topic-negative source. For health, BARRED/HealthE is the only candidate, and using it for user-message detection would change its task (response-side to request-side).
- If FinGuard-Bench is released with query-level labels, it is the one to check next for finance. Its label is "regulatory non-compliance", so task equivalence would still need checking.

### Gaps
- FinGuard-Bench availability and label semantics.
- Whether any MedQuAD-derived or r/legaladvice-derived classification set with human "advice request" labels exists. None surfaced in my searches.

## Q3. Which sources contain only harmful prompts (no negatives) or AI-generated labels?

### Takeaway
Positives only: AILuminate (all rows hazard-labelled) and Do-Not-Answer ("all instructions in this dataset are risky"). AI-generated labels: GovTech off-topic (GPT-4o generated pairs and labels), OffTopicEval ID queries (ChatGPT-5, manually verified), Aegis 2.0 response labels in part (LLM jury), LLMs & Legal Aid (GPT-4o), and the AWS denied-topics sample (Bedrock-generated test sets).

### Cited Findings
- AILuminate: human-generated prompts "designed to replicate distinct hazardous scenarios"; no benign controls. — [README](https://raw.githubusercontent.com/mlcommons/ailuminate/main/README.md); [arXiv:2503.05731](https://arxiv.org/html/2503.05731)
- Do-Not-Answer: GPT-4-generated questions, filtered and edited by the authors, positives only. — [arXiv HTML](https://arxiv.org/html/2308.13387)
- GovTech off-topic: GPT-4o generated both prompts and on/off-topic labels; human verification described only as optional ("can be applied"). — [arXiv HTML v2](https://arxiv.org/html/2411.12946v2)
- OffTopicEval: "ID queries: Generated by ChatGPT-5, manually verified"; OOD from MMLU. — [GitHub](https://github.com/declare-lab/OffTopicEval)
- Aegis 2.0: "Response safety labels generated using ensemble of 3 LLMs" where needed; prompt labels human. — [card](https://huggingface.co/datasets/nvidia/Aegis-AI-Content-Safety-Dataset-2.0/raw/d86bb8bedff51d25ac834ab7838f1cc61acb7a2c/README.md)
- LLMs & Legal Aid: "GPT-4o for zero-shot classification". — [arXiv:2501.01711](https://arxiv.org/abs/2501.01711)
- BARRED training data is synthetic (multi-agent debate). Its test sets are human-curated or human-verified synthetic. — [arXiv HTML](https://arxiv.org/html/2604.25203)

### Inferences
- AILuminate is the only source with human-written user prompts split by finance/health/legal, which makes it the strongest positives pool. It has 26/26/24 rows in the public demo, which is small.

### Gaps
- Per-prompt LLM-assistance flags for AILuminate are recorded internally (per the paper) but not published in the demo CSV.
