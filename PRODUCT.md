## Platform

web

## Stack

Static HTML, CSS and JavaScript in `site/leaderboard/`, no build step, reading `results.json` (schema `site/leaderboard/results.schema.json`). Kept inside this repository for now; later hosted as a research page on raxitlabs.com.

## Users

Readers of a raxIT Labs research page: engineers, security and platform leads evaluating guardrails for LLM applications, who want to know whether decision models (Jev, Kev, Open-Jev, Laya) are a credible alternative or complement to Amazon Bedrock Guardrails. Secondary: the raxIT team reviewing a run before publication.

## Product Purpose

Gold Rails is an open benchmark. It compares configured guardrail detectors across six selected task suites (a decision model with its questions, decision rule and frozen threshold, against Amazon Bedrock Guardrails with the policies configured for each suite) on the same held-out dataset, on quality, cost and latency. The dataset supplies the reference answers; Bedrock is a competitor, not the answer key. The results support a comparison on this dataset and these configurations, not a claim that one system can replace another as a complete service; untested capabilities, such as masking and grounding relevance, are listed on the page. The results page must make that comparison legible and traceable: every point is a frozen implementation evaluated on the test split, with its uncertainty, cost basis and ledger.

## Positioning

Decision models against a managed guardrail, measured on the same independent dataset with a published freeze manifest, dated tariffs and raw ledgers. Anyone can rerun it from this repository.

## Operating Context

- Six suites mirror Bedrock's comparable capabilities: content, prompt attacks, denied topics, word filters, sensitive information, grounding. Bias is a separate evaluation (B1 identity-mention error gaps, B2 counterfactual pairs, B3 decision-model bias via BBQ and discrim-eval), outside the six-suite aggregate.
- Headline metric: task score = 100 x 0.5 x (violation recall + benign pass rate), thresholds fitted on tuning rows and frozen before the test. Secondary: recall at a 5% tuning false-positive budget. 95% paired group-bootstrap intervals.
- Cost: measured usage x dated list price (Jev tokens, Bedrock text units), or allocated GPU serving time x hourly rate for self-hosted models. Unknown cost is shown as unknown, never zero.
- Planned chart (docs/reports/gold-rails-completion-plan.html): one quality-vs-cost chart per suite, plus Overall and Bias; horizontal axis toggles between cost per 1,000 and p95 latency; each point opens its configuration, threshold, sample sizes, errors, failures and interval; a table with the same numbers and JSON/CSV download.

## Capabilities and Constraints

- A suite that was not evaluated is labelled, never drawn as zero. Overall is ranked only when all six suites are evaluated.
- Current data (first benchmark, 23 Sep 2026) is interim: five of six suites (denied topics awaits reviewed rows), B1 and B3 bias only, contract v1.0 draft without sign-off. The page must show this status plainly.
- Overlapping intervals are not a win; the page must not imply rank separation it does not have.

## Evidence on Hand

- `benchmark/results/first-benchmark/`: leaderboards (original and corrected), bias.json, ledgers.
- No testimonials, customers or third-party endorsements exist; none may be invented.

## Product Principles

1. Every number traces to a manifest and ledger.
2. Uncertainty is part of the result, not a footnote.
3. Missing or unknown is shown as missing or unknown.
4. The comparison is decision models against Bedrock; baselines give scale, not headlines.
